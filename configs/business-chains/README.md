# 业务链路测试配置

这些文件可直接在「项目设置 → 业务链路 → 上传项目链路配置」中上传，也可在「项目模版维护 → 业务链路」中导入后加入模版候选。

| 文件                                 | 场景       | 说明                                                                                                                     |
| ------------------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| `supply-chain-ai-server-demo.json`   | 供应链交付 | 保留 Demo 的 `chain-ai-server`、核心节点 ID 和数据约定，覆盖客户下单、履约复期、原材料采购、生产制造、成品检验、成品发货 |
| `software-delivery-standard.json`    | 软件研发   | 需求、方案、开发、评审、测试、发布、线上观察与复盘                                                                       |
| `software-hotfix.json`               | 软件研发   | 线上故障受理、热修复、评审、回归、发布观察                                                                               |
| `software-delivery-bugfix-loop.json` | 软件研发   | 含测试失败后的 Bug 修复回路和人工介入断点                                                                                |

## 使用说明

- 所有文件均为 JSON，由页面自动转换为业务链路工作流定义后导入。
- JSON 转换支持 `condition`、`default` 和 `breakCondition`，因此 Bug 修复回路可直接上传。
- 业务链路配置文件不包含具体执行人、AI 伙伴或项目角色。导入后节点统一使用项目角色执行器，人员映射在项目实例启动阶段完成。
- `externalRefs` 不需要在节点上重复声明。系统会根据字段 `bindings` 中的 `system` 和 `objectId` 自动推导来源引用。
- 节点至少应声明 `id`、`name`、`stageCode`、`sequence` 和取数字段；字段使用稳定对象 ID 与来源路径，不要使用节点名称作为引用。
- 接入真实数据源时替换字段绑定中的对象 ID 和路径即可，不要修改 `stageCode`。
