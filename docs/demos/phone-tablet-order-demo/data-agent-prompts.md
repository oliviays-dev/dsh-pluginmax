# Data Agent 演示提示词

## 使用规则

- 所有提示词都在新会话中按顺序使用。
- 第二轮必须沿用第一轮的时间范围、异常口径和权限，不重新解释“异常”。
- 正式报告必须复用当前会话已有的 QueryRun，不重新执行 `metric_query` 或 `dataset_query_readonly`。
- 演示数据只覆盖华东、华南；未覆盖华北、西南。未覆盖区域必须显示为“未知”，不能按 0 处理。
- 手机和平板作为业务背景说明；Data Agent 使用现有 `category=数码` 查询，不推测具体型号、SKU 或 IMEI/SN。
- 订单事实来自资源市场注册的 `mcp-orders-phone-tablet-demo`，Data Agent 不持有 `mcp-wms-phone-tablet-demo` 的写工具。

## 1. 老板初步问询

### 输入

```text
请只读查询今天华东数码（手机/平板）订单异常。

要求：
1. 按订单异常 MVP 口径给一个简短 brief，不生成正式报告。
2. 必须包含订单量、异常量、异常率、支付失败量、取消量、履约超时量。
3. 说明查询时间范围、数据截止时间、权限覆盖、指标版本和 QueryRun 证据。
4. 区分“订单事实”和“待人工核实的原因”，不要仅凭订单字段推断具体 SKU 缺货。
5. 明确演示数据、非生产。
```

### 预期效果

Data Agent 显示查询过程，并返回类似下面的 brief：

```markdown
截至本次查询时刻，当前授权覆盖华东、华南。

今天华东数码订单 1,658 单，订单异常 126 单，异常率 7.6%。

- 支付失败：52 单
- 取消：31 单
- 履约超时：43 单

口径：订单异常 v1 = 支付失败 + 取消 + 履约超时，按订单去重；不含退款和金额异常。
数据来源：orders-facts，演示数据，非生产。
权限：当前授权华东、华南；华北、西南未覆盖，不推断为 0。
证据：展示 QueryRun、指标版本、数据截止时间和权限摘要。

初步判断：这是混合型订单异常，支付失败和履约超时需要分别核实；
当前订单数据不能确认具体 SKU、IMEI/SN 或成品仓作业状态。
```

### 讲解文案

> 这里 Data Agent 不只是一个聊天框。它先识别问题和授权数据范围，再调用认证指标返回异常构成、口径、截止时间和查询证据。订单域仍然保持只读，不会直接修改业务数据。

## 2. 计划员深入评估

### 输入

```text
沿用上一轮的时间范围、订单异常口径和权限，继续分析今天华东数码订单。

请按以下要求输出：
1. 按支付方式、渠道、商家和订单状态拆分异常，不要使用自由 SQL。
2. 结合订单金额说明影响，但不要输出无权限订单明细。
3. 给出订单级处置优先级：支付可恢复、成品仓再平衡、退款/取消/改约。
4. 明确哪些事实来自订单数据，哪些原因需要仓配或订单运营人工核实。
5. 给出两路执行建议：一路派给华东成品仓配负责人，一路派给履约 AI 伙伴。
6. 保留原 QueryRun 引用和口径，不生成正式报告。
```

### 预期效果

Data Agent 返回：

```markdown
异常仍是 126 单、7.6%，口径和权限范围与上一轮一致。

建议分三组处置：
1. 支付失败订单：核对支付重试、分期支付失败、订单保留时间。
2. 履约超时订单：核对受影响 SKU 的可分配库存、IMEI/SN 状态、成品仓出库能力和跨仓调拨条件。
3. 取消订单：核对客户主动取消、库存占用超时和促销价格问题。

订单数据可以定位区域、品类、渠道、商家、支付方式和金额；
但不能直接得出具体 SKU 库存不足、序列号未绑定或某成品仓作业异常。

建议人工任务：
- 委派王工核实华东成品仓 SKU、IMEI/SN、出库能力和跨仓调拨约束。

建议 AI 任务：
- 委派履约 AI 伙伴整理受影响订单，基于人工核实结果模拟订单再平衡并生成业务工单草稿。
```

### 讲解文案

> 这一步把“分析”推进到了“可执行分工”。Data Agent 仍然只读，但它把问题拆成需要人工核实的仓配约束和可以由 AI 承接的整理、模拟、草稿工作。

## 3. 正式复盘报告

### 输入

```text
请生成正式报告：《华东手机/平板订单异常处置复盘》。

必须复用当前会话已有的 QueryRun 和 QueryResult，不重新查询。
报告必须包含：
1. 数据口径、截止时间、权限覆盖和演示状态；
2. 126 单异常构成：支付失败 52、取消 31、履约超时 43；
3. 业务结果：83 单恢复履约，43 单退款、取消或改约；
4. 37 单通过成品仓订单再平衡工单 WO-RB-DEMO-1030-017 处置；
5. SKU、IMEI/SN、库存归属变更、保价运输和签收约束；
6. 不确定性、剩余风险和下一步动作。
```

### 预期效果

生成 Markdown 正式报告，并提供同源 HTML 派生入口。报告中明确写出：

```text
本报告基于当天已执行 QueryRun，不发起第二次数据查询。
手机/平板订单为数码品类业务场景；当前订单数据集不包含 SKU、IMEI/SN 和仓库库存字段。
这些信息来自人工仓配回执和业务工单，不在 Data Agent 订单指标中伪造。
```

### 讲解文案

> 正式报告不是重新查一遍数据，而是复用白天的 QueryRun 和执行回执。这样报告里的数字、口径和证据链能回到同一次数据快照。
