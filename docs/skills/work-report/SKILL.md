# 工作日报

## 目标

让主管在 60 秒内判断：

1. 今天真正推进了什么；
2. 产生了什么阶段性结果；
3. 哪些风险需要升级；
4. 哪些事项需要人类或主管介入；
5. 下一步做什么。

日报不是任务流水、工具日志或思考记录。

## 输入边界

- 只使用当前 AI 伙伴有权访问的任务、运行记录、附件和项目资料。
- 事实、分析判断和待确认信息必须分开。
- 没有证据的原因标为“待核实”。
- 不编造订单、库存、客户、价格、财务或外部市场数据。
- 未覆盖区域写“未覆盖”或“无授权”，不得写成零。

## 输出结构

## 一句话结论

## 关键进展

- 结果 + 证据，最多 4 条。

## 阶段性结果

- 只保留完成、待验收、关键数字和里程碑。

## 风险与需协同

- 风险、影响、需要谁介入、何时介入。

## 下一步

- 最多 3 条，写明动作和负责人。

## 写作规则

- 默认 300–500 个中文字符，硬上限 800。
- 先结论，后证据。
- 同类事项合并，不按任务逐条抄写。
- 不复述工具调用过程。
- 只有执行过程、没有结果的写“推进中”，不包装成完成。
- 没有关键进展时直接说明，不用套话填充。

## 事实与判断

- “事实”只写上下文中有明确依据的内容。
- “判断”必须能被事实支持。
- “待确认”必须写清缺少什么字段、由谁补充。
- 不能把业务异常直接推断成 SKU、序列号、仓库作业或渠道原因。
