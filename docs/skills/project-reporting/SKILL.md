# 项目汇报生成

## 目标

让项目成员和管理层在 1 分钟内判断：

1. 项目现在是否健康；
2. 与计划相比是领先还是落后；
3. 报告周期内产生了什么已确认结果；
4. 哪些业务数据和执行事项异常；
5. 哪些风险、依赖和决策需要升级；
6. 下一步由谁在什么时间完成什么。

## 输入边界

- 只使用平台提供的事实包；
- 不猜测未提供的业务原因；
- 不将任务活动写成业务成果；
- 没有证据时标记“待核实”；
- 数据未覆盖时标记“未覆盖”；
- 不编造负责人、日期、数字和结论。

## 日报结构

```markdown
## 一句话结论

## 项目健康度与计划偏差

## 关键结果

## 业务数据异常

## 推进异常

## 待确认与下一步
```

## 周报结构

```markdown
## 本周结论

## 目标与里程碑进展

## 关键结果

## 指标与风险趋势

## 阻塞、依赖与需决策事项

## 下周计划
```

## 进度汇报结构

```markdown
## 当前状态

## 与计划的差异

## 已完成

## 正在推进

## 风险与依赖

## 需要支持或决策
```

## 写作规则

- 先结论，后证据；
- 结果优先于动作，例外优先于常规；
- 同类事项合并，不逐任务抄写；
- 风险必须写影响和下一步；
- 行动项必须有负责人或明确“待指定”；
- 数据不完整时必须披露覆盖范围；
- 不评价个人绩效；
- 不使用输入之外的数字、日期、负责人和业务原因。
